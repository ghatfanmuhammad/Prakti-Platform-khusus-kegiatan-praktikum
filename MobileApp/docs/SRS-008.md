# SRS-008 — Data Praktikum di Firestore (Raihan)

Implementasi ada di tab **Data Praktikum**, route Expo Router `/explore`. Home (`/`) membuka tab Jadwal dari modul Firestore yang sama agar pembatasan akses juga berlaku di halaman awal. Entry point lokal yang sebelumnya membuka preview dilanjutkan untuk integrasi ini; source `JadwalPreview`, komponen jadwal, dan pengelola sesi dummy lama tetap disimpan sebagai referensi sprint sebelumnya dan tidak dipakai oleh route aplikasi.

## Menjalankan

Gunakan Node >=24.12.0 karena versi Firebase SDK yang dipakai membutuhkan versi tersebut. `.nvmrc` menunjuk Node 26.13.0 yang tersedia pada lingkungan pengerjaan.

```bash
nvm use
npm ci
cp .env.example .env.local
# Isi konfigurasi web app dari project Firebase tim ke .env.local.
npx expo start --clear
```

Firebase JS SDK digunakan untuk kompatibilitas Android, iOS, web, dan Expo Go. Tidak ada perubahan direktori native atau modul native tambahan.

## Integrasi dengan SRS-007 (Ghatfan)

1. Buat Cloud Firestore pada project Firebase tim, lalu isi empat variabel `EXPO_PUBLIC_FIREBASE_*` pada `.env.local`. Semua nilainya berasal dari konfigurasi **web app** pada Firebase Console. Jangan isi service account/private key di variabel publik.
2. Login SRS-007 harus memakai **default Firebase app yang sama**, melalui `getFirebaseServices()` di `src/lib/firebase.ts`. Inisialisasi Firebase Auth beserta persistence yang dibutuhkan sebelum merender layar data. Modul SRS-008 mengamati `onAuthStateChanged` dan tidak membuat halaman login kedua.
3. Sediakan dokumen `users/{FirebaseAuthUID}` berisi `role: 'asisten'` atau `role: 'praktikan'`. Profil dan role diprovisikan oleh backend/Admin SDK atau Firebase Console. Rules yang disertakan menolak penulisan profil dari client; Ghatfan perlu menggabungkan aturan registrasi profil secara aman pada SRS-007. Jangan membolehkan pengguna memilih/menaikkan sendiri perannya menjadi asisten.
4. Publikasikan rules dan indeks ke project tim setelah menggabungkannya dengan rules presensi/izin. File rules ini hanya mencakup data SRS-008 dan kontrak pembacaan profil, bukan aturan presensi SRS-009 atau izin SRS-010.

```bash
npx firebase-tools@latest deploy --only firestore:rules,firestore:indexes --project YOUR_PROJECT_ID
```

Tidak ada konfigurasi project, akun, role, atau rules remote yang dibuat atau dipublikasikan otomatis oleh perubahan ini. Tanpa konfigurasi layanan, layar menampilkan pesan layanan belum tersedia; tanpa akun, layar meminta pengguna masuk. Tidak ada fallback akun asisten atau data dummy pada layar Firestore.

## Skema dan kontrak data

Semua dokumen data memiliki `createdAt` dan `updatedAt` bertipe Firestore Timestamp, ditulis memakai `serverTimestamp()`.

| Path | Field |
| --- | --- |
| `users/{uid}` | `role` (`asisten` / `praktikan`), field profil lain milik SRS-007 |
| `classes/{classId}` | `kode`, `namaPraktikum`, `participantCount`, `scheduleCount`, `sessionCount` |
| `participants/{classId}_{uid}` | `classId`, `uid`, `nama`, `nim` |
| `classes/{classId}/schedules/{scheduleId}` | `hari`, `mulai`, `selesai`, `ruangan`, `sessionCount` |
| `classes/{classId}/sessions/{sessionId}` | `scheduleId`, `tanggal`, `modul`, `keterangan`, `status` |

`classId` dan `scheduleId` adalah ID dokumen, bukan label kelas. Jam menggunakan `HH:mm` dalam WIB. Tanggal menggunakan `YYYY-MM-DD`, divalidasi sebagai tanggal kalender dan harus sesuai hari jadwal. UID peserta harus sama dengan UID Firebase Auth pada profil praktikan; UID dengan panjang maksimal 128 karakter didukung, memakai huruf, angka, tanda hubung, atau garis bawah. Keanggotaan per kelas unik berdasarkan ID dokumen peserta; satu praktikan boleh mengikuti lebih dari satu kelas.

Asisten mengelola semua kelas, sesuai spesifikasi yang belum membatasi penugasan asisten per kelas. Praktikan hanya mengakses kelas yang memiliki keanggotaan dengan UID-nya. Query praktikan dimulai dari `participants` dengan filter `uid == currentUser.uid`, kemudian membaca dokumen kelasnya satu per satu. Praktikan tidak melakukan query seluruh kelas atau seluruh roster peserta. Pembatasan ditegakkan kembali oleh `firestore.rules`, termasuk akses langsung lewat SDK.

## Perilaku CRUD dan konsistensi

- Tambah, lihat, ubah, dan hapus kelas, peserta, jadwal, dan sesi tersedia melalui form dan daftar.
- Semua penulisan memakai transaksi Firestore. Profil asisten diverifikasi ulang ketika transaksi berjalan; keberhasilan hanya ditampilkan setelah transaksi dikonfirmasi server. Klik simpan ganda dikunci.
- Pendaftaran peserta menolak UID yang belum memiliki profil praktikan dan peserta yang sudah terdaftar pada kelas yang sama. Nama/NIM dapat diubah; mengganti akun dilakukan dengan hapus lalu tambah peserta baru.
- Perubahan counter parent dilakukan dalam transaksi yang sama. Kelas dengan anak data tidak dapat dihapus; jadwal yang dipakai sesi juga tidak dapat dihapus. Transaksi mencegah balapan antara penambahan anak dan penghapusan parent.
- Hari/jam jadwal yang dipakai sesi tidak dapat diganti; buat jadwal baru lalu pindahkan sesi yang belum dibuka. Pemindahan sesi memperbarui jumlah sesi pada kedua jadwal dalam transaksi yang sama.
- Sesi baru berstatus `belum_dibuka`. Hanya sesi yang belum dibuka yang dapat diedit atau dihapus. Sesi yang telah dibuka/dikasih presensi dipertahankan untuk riwayat. Transisi status hanya `belum_dibuka → dibuka → ditutup`; sesi tertutup tidak dapat dibuka kembali.
- Loading, daftar kosong, error izin/koneksi, dan tombol coba lagi tersedia. Snapshot cache yang belum dikonfirmasi server tidak dianggap sebagai daftar kosong. Penantian awal dibatasi 12 detik agar koneksi gagal tidak menampilkan spinner tanpa batas. Listener dibersihkan ketika kelas/akun berubah atau layar dilepas.
- Data tetap tersimpan di server dan diambil ulang setelah aplikasi dibuka kembali dengan login valid dan koneksi internet. Ini bukan implementasi penyimpanan offline permanen pada perangkat; penulisan transaksi memerlukan koneksi.

## Integrasi SRS-009/SRS-010

Gunakan `classId` dan `sessionId` pada skema di atas sebagai relasi presensi/izin. API diekspor dari `src/features/data-praktikum/index.ts`:

- `useDataIdentity(retry)` membaca identitas/peran dari Firebase Auth dan profil.
- `usePracticumClasses(identity, retry)` membaca kelas yang boleh diakses.
- `useClassRecords(identity, classId, retry)` menyediakan daftar peserta (asisten), jadwal, dan sesi, beserta status loading/error.
- `saveRecord(kind, classId, recordId, values)` melakukan create jika `recordId` null, atau update jika ada ID.
- `deleteRecord(kind, classId, recordId)` menghapus data dengan pemeriksaan relasi.
- `changeSessionStatus(classId, sessionId, nextStatus)` membuka/menutup sesi secara transaksional.

Jangan gunakan `useSessionManager` lama sebagai sumber data produksi; hook tersebut masih khusus preview dummy. Kedua route aplikasi sudah menggunakan modul Firestore. Tim dapat memakai hook Firestore yang sama jika ingin menyambungkannya ke desain layar jadwal/detail sesi lama.

## Verifikasi

```bash
npx expo lint
npx tsc --noEmit
npm test
npx expo export --platform web
```

Tes repository menguji CRUD, duplikasi peserta, role, relasi dan counter, perpindahan jadwal, tanggal invalid, proteksi riwayat sesi, serta UID panjang. Firestore diganti double transaksional pada tes ini; hasilnya tidak membuktikan deployment atau koneksi Firebase asli.

Tes rules membutuhkan Firestore Emulator dan menguji akses anonim, pembatasan kelas praktikan, query keanggotaan, larangan promosi role/penulisan praktikan, transaksi keanggotaan, dan status sesi tertutup. Tes hanya menyentuh project demo lokal `demo-prakti-srs008-tests`:

```bash
npx firebase-tools@latest emulators:exec --only firestore --project demo-prakti-srs008-tests "npm run test:rules"
```

Tanpa `FIRESTORE_EMULATOR_HOST`, tes rules diberi status **skip**, bukan dianggap membuktikan rules sudah lolos. Saat pengerjaan, emulator dan konfigurasi Firebase tim belum tersedia sehingga pengujian rules dan alur end-to-end dengan akun asli belum dijalankan.

## Checklist uji penerimaan bersama tim

1. Masuk sebagai asisten, tambah kelas, peserta dari akun praktikan valid, jadwal, dan sesi. Ubah masing-masing data dan pastikan hasil tersimpan.
2. Tutup/buka ulang aplikasi, masuk kembali bila diperlukan, dan pastikan data yang sama masih ada.
3. Masuk sebagai praktikan anggota kelas A, pastikan hanya jadwal/sesi kelas A yang muncul. Coba membaca kelas B melalui SDK: harus ditolak.
4. Praktikan tidak dapat membuka CRUD, mengubah role sendiri, atau mendaftarkan dirinya ke kelas lain.
5. Cabut keanggotaan kelas saat aplikasi praktikan terbuka: akses dan data kelas tersebut harus hilang.
6. Uji daftar kosong, koneksi putus sebelum dan sesudah pemuatan, serta pemulihan melalui Coba lagi.
7. Uji klik simpan ganda, penghapusan parent yang masih dipakai, tanggal tak valid, peserta ganda, dan sesi tertutup.
