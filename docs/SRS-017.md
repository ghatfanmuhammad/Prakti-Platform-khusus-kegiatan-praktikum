# SRS-017 — Push Notification Kegiatan

## Kapan notifikasi dikirim

| Pemicu (setelah tersimpan di Firestore) | Penerima | Ketuk notifikasi membuka |
| --- | --- | --- |
| Asisten membuka sesi (`changeSessionStatus` → `dibuka`) | Semua praktikan di kelas sesi | Halaman Presensi (SRS-012) |
| Asisten mengubah hari, jam, ruangan, atau labId jadwal | Semua praktikan di kelas | Jadwal |
| Asisten memindah sesi ke tanggal atau jadwal lain | Semua praktikan di kelas | Jadwal |
| Asisten menyetujui atau menolak izin | Pemilik pengajuan | Status Izin |

Notifikasi dikirim dari aplikasi asisten ke Expo Push API **setelah** transaksi Firestore selesai. Kalau penulisan data gagal, tidak ada notifikasi yang dikirim. Kalau pengiriman notifikasi gagal, perubahan data tetap tersimpan, dan asisten melihat ringkasannya, misalnya "Notifikasi terkirim ke 8 dari 10 praktikan (2 belum mengaktifkan notifikasi)".

## Kontrak data

| Path Firestore | Isi | Akses |
| --- | --- | --- |
| `pushTokens/{uid}` | `uid`, `token` (Expo push token), `platform`, `updatedAt` | Pemilik bisa tulis dan hapus. Asisten bisa `get` (tanpa `list`). |

Satu akun memakai satu token, yaitu token perangkat terakhir yang login. Token perangkat ini disimpan juga di AsyncStorage untuk pembersihan saat logout atau pencabutan izin, termasuk setelah restart aplikasi. Penghapusan memakai transaksi sehingga token perangkat lain yang lebih baru tidak terhapus. Pendaftaran yang selesai setelah logout dibatalkan sebelum menulis token. Logout menunggu pendaftaran yang sedang berjalan sebelum menghapus token.

## Izin dan status perangkat (SRS-018, bagian notifikasi)

Praktikan diminta izin notifikasi setelah login. Statusnya tampil di **Profil**. Di **Beranda** status hanya muncul kalau ada masalah:

- **Izin ditolak**: tombol *Izinkan Notifikasi*, atau *Buka Pengaturan* kalau sistem tidak bisa meminta izin lagi.
- **Perangkat gagal didaftarkan**: penyebabnya bisa koneksi terputus, project EAS belum dihubungkan, atau token gagal disimpan. Tersedia tombol *Coba Lagi*.
- **Tidak tersedia**: di web atau Expo Go Android.

Status diperiksa ulang otomatis saat aplikasi kembali aktif, termasuk bila sebelumnya aktif lalu izin dicabut dari Pengaturan. Penolakan izin tidak menghalangi jadwal, presensi, atau pengajuan izin. Dialog izin tidak diminta berulang saat resume.

## Penyiapan

Konfigurasi yang sudah ada pada branch Ghatfan dan dipertahankan:

- Project EAS `@ghatfan/prakti-app` sudah terhubung. `extra.eas.projectId` ada di `app.json`.
- Aplikasi Android `com.prakti.app` sudah terdaftar di Firebase `prakti-f938a`. `google-services.json` ada di root dan dirujuk lewat `android.googleServicesFile`.
- `eas.json` sudah dibuat dengan profil `development` (APK, dev client), `preview`, dan `production`.
- Rules token ada di repo dan diuji pada emulator. Status deployment rules produksi tidak diverifikasi dan tidak diubah dalam pekerjaan ini.

Kredensial FCM V1/APNs tidak dapat dibuktikan dari file konfigurasi repo dan belum diuji lewat pengiriman nyata. Dokumen branch sebelumnya mencatat setup FCM V1 berikut sebagai pekerjaan manual pemilik akun Expo. Periksa apakah sudah diselesaikan sebelum membuat development build:

1. Buka Firebase Console → Project settings → Service accounts → **Generate new private key**. Simpan file JSON-nya di luar repo. File ini rahasia dan **jangan di-commit**.
2. Jalankan `npx eas-cli@latest credentials -p android`, lalu pilih profil `development` → *Google Service Account* → *Manage your Google Service Account Key for Push Notifications (FCM V1)* → *Set up a Google Service Account Key for Push Notifications (FCM V1)* → *Upload a new service account key*, lalu pilih file dari langkah 1.

Tanpa langkah ini, perangkat tetap bisa didaftarkan, tetapi Expo menolak pengiriman ke Android dengan galat `InvalidCredentials`.

Build ulang development: `npx eas-cli@latest build --profile development --platform android`. Pasang APK-nya, lalu jalankan `npx expo start --dev-client`.

### Bukti empat kejadian dan penerima

Tes emulator memanggil operasi produksi dari `notifikasi/aksi.ts`, melakukan transaksi Firebase SDK nyata, lalu mengganti HTTP Expo dengan mock yang mencatat payload. Ini membuktikan pemicu, urutan setelah commit, dan penerima; **bukan bukti push sampai di perangkat**.

| Kejadian | Data server setelah operasi | Tujuan HTTP yang direkam |
| --- | --- | --- |
| Sesi dibuka | status = dibuka | Hanya token anggota kelas |
| Jadwal berubah | Ruang/lab jadwal diperbarui | Hanya token anggota kelas |
| Izin diterima | status = Disetujui | Hanya token pemilik izin |
| Izin ditolak | status = Ditolak | Hanya token pemilik izin |

Token akun di luar kelas sengaja disiapkan dan tidak muncul pada keempat payload. Pengulangan keputusan terminal ditolak tanpa mengirim payload baru. Tes unit tambahan memeriksa commit gagal tidak mengirim push; jadwal tidak berubah/pembuatan baru tidak mengirim; perubahan labId saja mengirim; peserta duplikat, akun tanpa token, kegagalan baca token, dan kegagalan batch HTTP tetap dihitung benar (batch pertama dan terakhir tetap dihitung jika batch kedua gagal).

### Izin notifikasi ditolak

Adapter API perangkat dimock untuk menguji penolakan sementara/permanen, pemeriksaan resume tanpa dialog, channel Android sebelum prompt/token, iOS provisional, web, dan Expo Go Android. Saat ditolak, fungsi mengembalikan status `izin_ditolak`, tidak mengambil token, dan sinkronisasi menghapus hanya token perangkat yang sebelumnya tersimpan. Tes restart menggunakan AsyncStorage double yang mempertahankan data. UI tetap menyediakan tombol Izinkan Notifikasi/Buka Pengaturan dan fitur utama tetap terpisah dari status push; dialog serta rendering UI pada perangkat belum diuji.

## Tes perangkat yang masih diperlukan

`adb devices` tidak menemukan perangkat. Belum menjalankan build EAS, pengiriman Expo/FCM/APNs nyata, pembacaan push receipts, banner foreground/background/terminated, dialog izin OS, dan ketuk notifikasi pada perangkat. Kredensial dan deployment produksi juga belum diverifikasi.

Gunakan development build (lihat [dokumentasi SDK 58](https://docs.expo.dev/versions/v58.0.0/sdk/notifications/)). Login praktikan anggota kelas pada perangkat A, praktikan di luar kelas pada B, dan asisten di perangkat lain. Uji empat kejadian saat foreground/background/terminated; A menerima, B tidak menerima. Putuskan izin milik B: hanya B menerima. Tolak izin pada A, pastikan Profil/Beranda menjelaskan status dan aplikasi tetap bisa dipakai. Cabut izin setelah sempat aktif, buka aplikasi lagi, lalu pastikan token perangkat dilepas. Uji logout dan login akun lain, serta ketuk notifikasi pada keadaan aplikasi berbeda.

## Batas implementasi

Pengiriman tetap memakai arsitektur branch anggota: dari aplikasi asisten setelah commit, tanpa backend queue/retry persisten. Jika aplikasi mati persis setelah commit sebelum HTTP, notifikasi bisa tidak terkirim; perubahan data tetap tersimpan. Ringkasan menghitung tiket diterima Expo, bukan jaminan tampil di OS. Satu akun memakai satu perangkat terakhir. Rules dan konfigurasi kredensial harus ditinjau sebelum merge/deploy; pekerjaan ini tidak melakukan merge ke main atau deployment.
