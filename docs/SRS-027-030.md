# SRS-027 s.d. SRS-030: Pembayaran denda (Midtrans Sandbox) & finalisasi antarmuka

PIC: Ghatfan. Branch: `feature/pembayaran-midtrans`.

## Alur

```
Aplikasi ──(callable buatTransaksi {dendaId})──▶ Cloud Functions ──(Snap API + server key)──▶ Midtrans
   ▲                                                  │
   │ onSnapshot denda/pembayaran                      ▼
Firestore ◀──(Admin SDK, setelah verifikasi)── midtransNotifikasi ◀──(HTTP notification)── Midtrans
```

1. Praktikan menekan **Bayar** di layar Tagihan. Aplikasi hanya mengirim `dendaId`.
2. `buatTransaksi` memeriksa pemanggil adalah praktikan pemilik denda dan denda belum lunas/dibebaskan,
   lalu memesan `pembayaran/{orderId}` (status `pending`) dan mengunci denda (`pending`) dalam satu
   transaksi Firestore. Setelah itu baru Snap dipanggil. Nominal diambil dari dokumen denda di server.
3. Aplikasi membuka `redirect_url` lewat `expo-web-browser` dan kembali melalui `prakti://pembayaran`.
   Hasil redirect **tidak** dipakai untuk menentukan status.
4. `midtransNotifikasi` memverifikasi `signature_key` (SHA512), lalu mengonfirmasi ulang lewat Status API,
   mencocokkan nominal, dan baru kemudian mengubah status pembayaran & denda.
5. Trigger Firestore mengirim push ke praktikan pemilik (denda baru, berhasil, gagal, tertunda).

## Kontrak data untuk SRS-025 (pembuat denda)

`denda/{dendaId}` ditulis **hanya oleh server** (rules: `write: false`). Gunakan ID yang sama dengan
presensi, `${classId}~${sessionId}~${praktikanId}`, lalu buat dengan `create()` agar satu keterlambatan
pasti hanya menghasilkan satu tagihan.

| Field | Tipe | Keterangan |
|---|---|---|
| `praktikanId` | string | UID praktikan |
| `classId`, `sessionId` | string | sesi terkait |
| `attendanceId` | string | ID dokumen `attendance` |
| `sesiNama` | string | label tampilan, mis. `Basis Data · Modul 2` |
| `tanggal` | string | `YYYY-MM-DD` |
| `menitTerlambat` | int | menit setelah grace period |
| `nominal` | int | rupiah, nominal tetap |
| `status` | string | `belum_dibayar` saat dibuat; `dibebaskan` untuk izin yang disetujui |
| `orderIdTerakhir` | string/null | diisi `buatTransaksi` |
| `createdAt`, `updatedAt` | timestamp | |

Status `pending`, `lunas`, dan `gagal` hanya diubah oleh fungsi pembayaran. Tipe TypeScript-nya ada di
`src/features/pembayaran/kontrak.ts`. Push "Tagihan denda baru" otomatis terkirim saat dokumen dibuat
dengan status `belum_dibayar`.

Untuk menguji sebelum SRS-025 selesai, buat dokumen contoh lewat Firebase Console (koleksi `denda`).

## Pemetaan status (SRS-028)

| Midtrans `transaction_status` | pembayaran | denda |
|---|---|---|
| `settlement`, `capture` (fraud `accept`) | `success` | `lunas` |
| `pending`, `capture` + fraud `challenge` | `pending` | tetap `pending` |
| `deny`, `cancel`, `expire`, `failure` | `failed` | `gagal` (hanya bila order ini yang terakhir) |
| lainnya (`refund`, `authorize`, ...) | diabaikan | diabaikan |

Status tidak pernah mundur: `success` final, dan `pending` tidak menimpa `success`/`failed`.
Notifikasi ganda tidak menulis apa pun sehingga push tidak terkirim dua kali.
Selama transaksi lama masih berlaku (60 menit), menekan Bayar lagi membuka tautan yang sama.

## Setup (sekali, oleh pemilik proyek Firebase)

1. Daftar akun Midtrans, pilih lingkungan **Sandbox**, salin **Server Key** (`SB-Mid-server-...`).
2. Simpan sebagai secret (butuh paket Blaze):
   ```
   npx firebase-tools functions:secrets:set MIDTRANS_SERVER_KEY
   ```
3. Deploy:
   ```
   npm --prefix functions ci
   npx firebase-tools deploy --only functions,firestore:rules
   ```
4. Di dashboard Midtrans Sandbox → Settings → Payment → **Notification URL**, isi URL fungsi
   `midtransNotifikasi`, mis. `https://us-central1-prakti-f938a.cloudfunctions.net/midtransNotifikasi`
   (URL pasti tampil di output deploy).
5. Aplikasi perlu development build baru karena `expo-web-browser` dan `scheme` di `app.json` berubah.

Pembayaran uji memakai simulator Midtrans Sandbox (tidak memakai uang asli).
